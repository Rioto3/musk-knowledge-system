# 知識ベース管理ガイドライン

## 基本原則
1. **階層構造の維持**: 根本原理と応用例を明確に区別する
2. **相互参照の徹底**: 知識間の関連性を常に明示する
3. **継続的更新**: 新しい洞察や事例を定期的に追加する
4. **冗長性の排除**: 同じ知識の重複を避け、参照関係で表現する

## 知識の種類と管理方法

### 1. 根本原理 (`/principles/`)
- 物理学、経済学、心理学などの基礎的な法則
- 複数分野における共通原理
- 形式：マークダウン形式で、定義、適用範囲、例外条件を明記

### 2. 事例研究 (`/case-studies/`)
- 実際のプロジェクトや意思決定における適用例
- 成功例と失敗例の両方を含む
- 形式：背景、課題、適用原理、結果、教訓の構造化記述

### 3. 思考パターン (`/patterns/`)
- 複数の根本原理を組み合わせた問題解決アプローチ
- 再利用可能な思考フレームワーク
- 形式：パターン名、適用条件、ステップ、注意点の定型化

### 4. テンプレート (`/templates/`)
- Issue、プロジェクト管理用の標準フォーマット
- Sonnet/Haiku向けタスク分類基準
- 形式：マークダウンテンプレートとメタデータ

## 知識ベース拡張プロセス

1. **新規提案**: Issueとして追加候補を提案
2. **検証**: 既存知識との整合性と独自性の確認
3. **構造化**: 適切なカテゴリと形式での整理
4. **関連付け**: 既存知識との相互参照の設定
5. **統合**: プルリクエストによる追加

## 品質基準
- **明確性**: 曖昧さのない表現
- **簡潔性**: 無駄のない記述
- **検証可能性**: 具体的な適用方法の明示
- **拡張性**: 新しい文脈への適用可能性
- **相互参照**: 関連知識への明示的なリンク
